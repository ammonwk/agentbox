# agentbox v2

One place to see, start and continue every coding-agent session on this
machine — Claude Code, Codex, Devin and omp — across every subscription you are
logged into, with new sessions placed on whichever account has the most room.

This file is the contract between the pieces. If a change contradicts it,
either the change is wrong or this is: say which, in the same commit.

## What changed from v1, and why

v1 ran omp only, over ACP, in detached host processes, and let other agents
spawn omp agents as MCP subagents. v2 drops the omp-only host entirely. What
it keeps from v1: the subagent MCP (see below), skills management, the
machine and per-session load metrics, worktree reclaim, repos, PR lookup, the
router and the WebSocket split between hot state, cold state and metrics.

What it takes from switchyard: reading every provider's own transcripts as the
source of truth, tmux as the only way a session is driven, and adopt
(stop a CLI session, resume it under agentbox) with its check-before-kill
ordering.

## A session is the provider's, not ours

Every provider already writes a durable transcript. agentbox never writes a
second copy of the conversation; it reads theirs.

| provider | transcript | live-process signal | resume |
|---|---|---|---|
| claude | `$CLAUDE_CONFIG_DIR/projects/<slug(cwd)>/<uuid>.jsonl` | `$CLAUDE_CONFIG_DIR/sessions/<pid>.json` (`sessionId`) | `claude --resume <uuid>` from the original cwd |
| codex | `$CODEX_HOME/sessions/YYYY/MM/DD/rollout-<iso>-<uuid>.jsonl` | `codex` pid, its `CODEX_HOME` from `/proc/<pid>/environ`, cwd, rollout mtime | `codex resume <uuid>` |
| devin | `~/.local/share/devin/cli/sessions.db` + `transcripts/<id>.json` | `session_locks/` | `devin -r <id>` |
| omp | `~/.omp/agent/sessions/<slug>/<iso>_<uuid>.jsonl` | `omp` pid + file mtime | `omp -r <id>` |

The database holds only what the provider cannot: which account a session is
pinned to, its claim on that account, whether it is Big, the tmux session it
runs in, a label, archive state, and the metrics we collect for calibration.
A session row is keyed by `(provider, agentSessionId)` and gets a short
agentbox id for URLs.

## Every agentbox session is a real TUI in agentbox's own tmux

`tmux -L agentbox`, one tmux *session* per agent session, named
`ab-<shortid>`. One session each (not one window each in a shared session) so
that a terminal and a browser can both be attached without switching each
other's windows.

This is what makes "start in the CLI, continue in the app, and back" a
non-event: `agentbox claude` starts the agent in tmux and attaches your
terminal; the web UI attaches a PTY to the same tmux session and renders it
with xterm.js; detaching either leaves the agent running. The structured
timeline beside it comes from the transcript, not the screen.

A session started with plain `claude` in some other terminal is still
discovered from its transcript and shown read-only. **Adopt** moves it into
agentbox: prove the resume will land (transcript exists at the slug of the
resume cwd), SIGTERM the process, wait for it to exit, `--resume` in tmux on
the same account. Never kill first.

Input from the web goes through `tmux load-buffer` + `paste-buffer` (bracketed
paste, so multi-line text stays one prompt) and a separate `Enter`. Every write
re-proves the target pane from the live pid rather than trusting a stored pane
id — tmux renumbers panes when its server restarts.

## Accounts

An account is a provider plus a credential home:

| provider | isolation | default account |
|---|---|---|
| claude | `CLAUDE_CONFIG_DIR=<home>` | `~/.claude` (env unset) |
| codex | `CODEX_HOME=<home>` | `~/.codex` |
| devin | `WINDSURF_API_KEY` read from `<home>/devin/credentials.toml` (login runs with `XDG_DATA_HOME=<home>`) | the default XDG dir (env unset) |
| omp | omp balances its own credential pool; one implicit account | `~/.omp` |

Non-default homes live in `~/.local/share/agentbox/accounts/<id>/`. Shared
configuration is symlinked in from the default home so every account behaves
the same: for claude `settings.json CLAUDE.md skills agents commands plugins
hooks output-styles statusline* keybindings.json`, for codex `config.toml
AGENTS.md skills rules prompts hooks.json`, for devin `config.json` into
`<home>/config/devin/`. Credentials, `.claude.json`, transcripts and codex's
sqlite state are never shared. A new claude home gets its own `.claude.json`
seeded from an allowlist of preference keys in `~/.claude.json` (onboarding
done, theme, `mcpServers`, completed migrations) so it skips the first-run
screens; identity, usage cache and per-project state are never copied.

Transcripts are deliberately **not** shared between accounts. Sharing them
would let `claude --resume` pick up another account's session, which is
exactly the cache invalidation this whole feature exists to avoid. agentbox
always resumes a session on the account it started on.

Never copy credentials between homes. Both Claude and Codex rotate refresh
tokens; two homes holding the same refresh token means one of them is logged
out the next time the other refreshes. Every account gets its own login.

agentbox never refreshes a token itself. Usage reads that hit an expired token
report `stale` with the last good reading; the next CLI run on that account
refreshes it.

### Login

Driven from the web UI; the CLI runs in a PTY and the URL/code it prints is
shown to you.

- claude: `CLAUDE_CONFIG_DIR=<home> claude auth login`; show the URL, accept a
  pasted `code#state`, done when `.credentials.json` appears.
- codex: `CODEX_HOME=<home> codex login --device-auth`; show the verification
  URL and one-time code; done when the process exits 0.
- devin: `XDG_DATA_HOME=<home> XDG_CONFIG_HOME=<home>/config devin auth login
  --force-manual-token-flow`; show the URL, accept the pasted token.
- omp: `omp auth-broker login <provider>`; omp stores it in its own pool.

Codex and omp use fixed localhost callback ports, so logins run one at a time.

### Usage

Each account publishes a list of windows:

    { id, kind: "short" | "weekly" | "daily" | "monthly", label,
      usedPct, resetsAt, windowMs, scope?: { model } }

- claude: `GET https://api.anthropic.com/api/oauth/usage` with
  `anthropic-beta: oauth-2025-04-20` (every 3 min per account, backing off on
  429), plus the free `cachedUsageUtilization` in each home's `.claude.json`
  whenever it changes. `five_hour` → short, `seven_day` → weekly,
  `limits[kind=weekly_scoped]` → weekly with a model scope.
- codex: `rate_limits` on `token_count` events in rollouts (free, as fresh as
  the last turn), plus `GET https://chatgpt.com/backend-api/wham/usage` for
  accounts with nothing running. Weekly only since August 2026, but the code
  takes whatever windows it is given.
- devin: best effort from `GetUserStatus`; absent is shown as unknown.
- omp: `omp usage --json`.

Every reading is also written to `usage_samples`, which is the raw material for
calibration.

## Placing a new session (the balancer)

`src/core/balancer.ts` is a pure function from account state to a choice, with
the full reasoning attached. Everything is in **weekly percentage points**.

Inputs per account: weekly used `W` and reset, short-window used `F` and reset
(claude), and the outstanding claims of its active sessions.

- A session **claims** `claimNormal` (5) points of weekly, or `claimBig` (20)
  if started as a Big session. Its outstanding claim is
  `max(0, claim − consumedSoFar)`, where consumption is the account's observed
  weekly increase apportioned across its active sessions by token-weighted
  cost. A claim lapses when the session has been idle `claimIdleMin` (60).
- Effective weekly `W' = W + Σ outstanding`. Effective short `F' = F + Σ
  outstanding × 100 / shortWindowInWeekly` (24: one full 5-hour window is about
  24 weekly points), because the next hour of a session lands in the current
  short window.
- **Gate**: an account can take a new session while `W' < 100` (and, for a
  model with a scoped weekly limit, that scope's `W' < 100`).
- **Rank** (claude): room — short-window leg room `100 − F'`, raised toward
  100 as the short window's reset approaches within `resetHorizonMin` (60): an
  account at 80% that resets in ten minutes is nearly fresh — then capped by
  weekly headroom in short-window units, `(100 − W') × 100 /
  shortWindowInWeekly`: an account at 97% weekly has about an eighth of a
  window left however idle its 5-hour is. Accounts within `tieBand` (10)
  points of the best are tied; the tie goes to the one with the most weekly
  left per hour until its weekly reset (use it or lose it).
- **Rank** (weekly only, codex): most weekly left per hour until reset.
- Nothing eligible: say so, and let a manual pick override.

Worked example (the one this was designed from): A is 92% weekly / 0% short,
B is 12% / 80%. First session → A (room 33 — its 8 weekly points are a third
of a 5-hour window — vs B's 20). A is now W' 97, so its room is capped at 12.5
and the second goes to B (20). B's short window is then spoken for (F' 101,
room 0), so the third goes back to A, which is then at W' 102 and stops taking
sessions.

Every placement writes an `assignments` row holding every candidate's inputs,
derived numbers and the config in force, so a week of placements can be
replayed against different settings.

### Calibration

`src/core/calibration.ts` reads the metrics tables and proposes settings:

- `shortWindowInWeekly`: regression of weekly increase on short-window
  increase over intervals where neither window reset.
- `claimNormal` / `claimBig`: the distribution (median, p75, p90) of what
  sessions actually consumed, split by the Big flag.
- how often a placement was followed by a rate-limit hit on that account.

## Master session

`agentbox mcp` is an MCP server for one conductor session with a compact view
of the whole fleet: `fleet`, `read_session`, `send`, `spawn`, `accounts`,
`archive`. The conductor is an ordinary claude session started from the UI
with that server attached; nothing about it is special to the rest of the app.

## Subagent MCP

`agentbox subagent-mcp` is a separate MCP server, for any agent that wants to
delegate: `agent`, `send_message`, `collect`, `list_agents`, `transcript`,
`interrupt`, `stop_agent`, `workflow`. Each agent is an `omp acp` process
owned by the MCP server, run in the caller's working directory (or `cwd`) and
blocked on like a function call; `workflow` runs a script that fans many out.
It needs neither the agentbox server nor the database, and its agents die with
it. The model is `AGENTBOX_SUBAGENT_MODEL`, else
`opencode-go-responses/muse-spark-1.3-contributor`.

It keeps its data under `$AGENTBOX_HOME`:

- `subagents/<pid>-<n>-<name>/` — one per spawn: `system.md` (the prompt omp
  was launched with), `meta.json` (identity, the brief, and omp's session
  id), `state.json` (a snapshot refreshed every 2s) and `transcript.jsonl`
  (the event log). Pruned after 7 days.
- `live/*.live` — one pre-rendered status line per agent that is running or
  holding an uncollected answer, and per workflow:
  `<unix s>\t<cwd>\t<owner>\t<text>`, read by a status-line script.

omp itself runs without `--session-dir`, so each agent's own transcript lands
in `~/.omp/agent/sessions` and the fleet lists it as an external omp session;
`meta.json`'s `ompSessionId` is what ties the two together. Code:
`src/mcp/subagent.ts` over `src/subagents/`.

## Security

The server binds loopback and requires, on every mutating request, an
`x-agentbox: 1` header plus an Origin (when present) and Host that are
loopback. That blocks a web page in your browser from driving the API, which
v1 allowed. Skill paths are confined to the skill roots by realpath; skill
names are validated as a single path segment.

WebSockets:

- `/ws` — server pushes `hot`, `cold`, `metrics`, and `timeline` for the one
  session the client `watch`es (first frame `reset: true` with the newest page,
  then increments; a tool event may be re-sent with the same id when its result
  arrives — replace by id).
- `/ws/term/:id` — a live terminal on the session's tmux. Server → client:
  binary frames of raw terminal output. Client → server: text frames
  `{"type":"input","data":"…"}` and `{"type":"resize","cols":N,"rows":N}`.
  Closing the socket detaches; the agent keeps running.
